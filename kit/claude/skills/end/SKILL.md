# 세션 종결

이 지시는 **커밋 · 푸시 · PR · 원격 dev 병합 · 보관까지의 승인**을 담는다. 절차 안에서 "커밋할까요 · 병합할까요"를 다시 묻지 않는다. 아래 "멈추는 조건"에 걸릴 때만 멈춘다.

비용은 "호출 횟수 × 대화 크기"다. **점검 스크립트 결과를 믿고, 확인하려고 따로 명령을 부르지 않는다.** 명령은 아래 묶음대로 한 번에 부르고, 중간 설명 글을 쓰지 않는다. 깨끗한 세션이면 호출 6번 안팎으로 끝난다.

## 하는 일 (이 순서)
| # | 하는 일 | 스크립트 결과의 어느 항목 |
|---|---|---|
| 1 | 점검 스크립트를 한 번 돌린다 | — |
| 2 | 대화가 20만 토큰을 넘으면 압축을 권하고 멈춘다 | `tokens` |
| 3 | 돌고 있는 서브에이전트 · 하위 세션이 있으면 멈춘다. 멈춰 있는 하위 세션은 보고에만 적는다 | `running` · `openChildren` |
| 4 | 커밋 전 변경을 커밋한다 | `dirty` |
| 5 | 지워질 무시 파일이 있으면 멈춘다 | `ignored` |
| 6 | 원격 dev에 없는 커밋을 병합한다: 푸시 전 점검 → 푸시 → PR → 병합 | `merge` |
| 7 | 원격 브랜치를 지운다 | `merge` · `branch` |
| 8 | 워크트리 안 서버 · 프로세스를 내린다 | `processes` |
| 9 | 이 워크트리에서 띄운 도커를 내린다 | `docker` |
| 10 | 원래 체크아웃의 dev를 당겨 받는다 | `origin` |
| 11 | 보관 뒤 정리를 대기 목록에 등록한다 | — |
| 12 | 한 번 보고하고, 세션을 보관한다 | — |

보관 뒤의 일(임시 폴더 · 워크트리 폴더 지우기, 워크트리가 사라진 뒤 로컬 브랜치 지우기)은 등록해 둔 대기 목록을 훅이 처리한다(다른 세션이 시작되거나 입력을 받을 때 돈다). **이 세션은 자기 워크트리 · 로컬 브랜치 · 대화 기록 · 도커 볼륨을 지우지 않는다.**

## 호출 묶음
**① 점검 (1번)**
```bash
node ~/.work-dash/app/core/closeout.js "$CLAUDE_CODE_SESSION_ID" --end
```
한 줄 JSON이 나온다. 없는 항목은 해당 없음이다. `ok: false`나 `gone: true`면 멈추고 그대로 알린다.

**② 압축 (2번) — `tokens`가 200000을 넘을 때만**
- 사용자의 요청에 "압축 없이"가 없으면 "대화가 깁니다(약 N만 토큰). `/compact`를 한 뒤 `/end`를 다시 불러 주세요. 그대로 끝내려면 '압축 없이 종결'이라고 해 주세요" 한 줄만 쓰고 **바로 턴을 끝낸다.** 보관하지 않는다.
- "압축 없이"가 있으면 그대로 진행한다.

**③ 커밋 · 푸시 · PR (4 · 6번) — 한 명령으로 묶는다**
- 이 세션에서 `~/.work-dash/RULES-COMMIT.md`를 아직 읽지 않았으면 먼저 읽는다(커밋 나누기 · 메시지 · PR 본문 형식).
- 커밋 범위: `worktree: true`면 워크트리의 변경 전부다. 워크트리 꼭대기(`dir`)에서 `git -C <dir> add -u && git -C <dir> add -A -- . ':(top,exclude).claude' ':(exclude).playwright-mcp' ':(exclude).DS_Store'`(추적 중인 `.claude` 파일의 변경은 넣고, 추적하지 않는 `.claude`는 뺀다). `worktree: false`(원래 폴더에서 연 세션)면 **이 세션이 고친 파일만** 이름으로 더한다. 누가 고쳤는지 모르는 파일은 커밋하지 않고 보고에 적는다.
- `dirty.files`의 새 파일(`??`) 중 비밀로 보이는 것(`.env`, 키 · 인증서 · `credentials` 등)이 있으면 커밋하지 않고 멈춰 묻는다. 새로 올린 파일 이름은 보고에 적는다.
- `dirty`가 없고 `merge.ahead`가 0이면 ③ · ④를 건너뛴다.
- `merge.openPr`가 있고 그 `base`가 `merge.base`와 같으면 그 PR을 쓴다(새로 만들지 않는다). `base`가 다르면(예: `main`) 병합하지 않고 멈춰 묻는다. `main` · `master`로는 병합하지 않는다.
- 푸시 전 점검은 그 저장소의 `AGENTS.md` · `CLAUDE.md`에 적힌 "커밋 · 푸시 직전" 명령이다. 같은 묶음 안에서 `&&`로 잇는다:
  `git add … && git commit … && <푸시 전 점검> && git push -u origin <branch> && gh pr create --base <merge.base> --title … --body …`
- PR 본문에 개인 파일 경로(`~/.work-dash/…`)나 에이전트 · 세션 이름을 쓰지 않는다.

**④ 병합 · 원격 브랜치 지우기 (6 · 7번)**
```bash
gh pr merge <번호> --merge && git push origin --delete <branch>
```
`--delete-branch`는 쓰지 않는다(로컬 브랜치를 건드린다). 원격 브랜치 지우기가 "없는 참조"로 실패하면 저장소가 이미 지운 것이니 무시한다. 병합할 것이 없었어도 `merge.merged`가 있고 원격에 이 브랜치가 남아 있으면 원격 브랜치만 지운다.

**⑤ 내리기 · 당겨 받기 · 등록 (8~11번) — 한 명령으로 묶고, 각 줄 끝에 `;`를 써서 하나가 실패해도 다음으로 간다**
- 프로세스(`processes`의 것만, `otherProcesses`는 건드리지 않는다): 시작 시각이 그대로일 때만 내린다.
  `[ "$(LC_ALL=C ps -o lstart= -p <pid> | tr -s ' ' | sed 's/ *$//')" = "<started>" ] && kill <pid>`
  `kill -9`는 쓰지 않는다. 다르면 건너뛰고 보고에 적는다.
- 도커: `docker.compose`의 묶음마다 `docker compose -p <project> down --rmi local`, `docker.containers`는 `docker rm -f <이름…>`. 볼륨 옵션(`-v`)과 `--rmi all`은 쓰지 않는다.
- 당겨 받기: `origin.branch`가 `merge.base`와 같고 `origin.dirty`가 0일 때만 `git -C <origin.dir> pull --ff-only`. 아니면 건너뛰고 보고에 적는다.
- 등록(마지막 줄, 항상):
  `node ~/.work-dash/app/core/afterarchive.js register "$CLAUDE_CODE_SESSION_ID"`
  `ignored`를 사용자에게 보이고 답을 받아 처리했으면(옮길 것은 옮긴 뒤) 끝에 `--ignored-ok`를 붙인다. 워크트리에 남은 무시 파일은 폴더와 함께 지워진다. 묻지 않았거나 답을 받지 못했으면 붙이지 않는다(그러면 워크트리 폴더를 지우지 않는다).
  한 줄 JSON이 나온다. `worktree`가 `false`면 워크트리 폴더가 남는다고 보고에 적는다. `ok: false`이고 `kind`가 `busy`면 한 번 더 부른다. 그래도 `ok: false`면 보관은 하되, 임시 폴더 · 워크트리 · 로컬 브랜치가 남는다고 보고에 적는다.

**⑥ 보고와 보관 (12번)**
- 보고는 몇 줄로: 병합한 PR, 내린 것, 남는 것(`stash`, 멈춘 하위 세션 `openChildren`, 진행 중 항목 `inProgress`, 건너뛴 것, `unknowns`).
- 보고 글과 **같은 답 안에서** 보관 도구 `mcp__ccd_session_mgmt__archive_session`을 `session_id: "self"`로 부른다. auto 모드에서는 첫 호출이 "분류기 판정 없음"으로 돌아올 수 있다. 그때는 돌려준 입력 그대로 한 번 더 부른다.

## 멈추는 조건
멈추면 무엇 때문인지와 다음에 할 수 있는 일을 답으로 남기고 턴을 끝낸다. **보관하지 않는다.** 사용자가 풀고 다시 부르면 ①부터 다시 돈다.

| 조건 | 어떻게 |
|---|---|
| `running`이 있다 | 무엇이 돌고 있는지 알린다. 끝나기를 기다리거나 멈추는 것은 사용자가 정한다 |
| `ignored`가 있다 | 워크트리와 함께 사라지는 파일이다. 목록을 보이고 묻는다(옮길지 · 버릴지). 답을 받으면 처음부터 다시 진행하고, 옮길 것을 옮긴 뒤 등록 때 `--ignored-ok`를 붙인다(남은 것은 워크트리와 함께 지워진다) |
| `merge.base`가 `null`이다 | 원격에 `dev` · `Dev` · `develop`이 없다. 어디로 병합할지 묻는다 |
| `merge.onBase`다 | 통합 브랜치에서 직접 일한 세션이다. 커밋 · 푸시를 어떻게 할지 묻는다 |
| `worktree: false`이고 `merge.commits`에 이 세션이 만들지 않은 커밋이 있다 | 브랜치 전체가 dev로 들어간다. 커밋 목록을 보이고 묻는다 |
| `sharedWith`가 있다 | 같은 폴더를 쓰는 열린 세션이 있다. 알리고, 커밋 · 병합만 할지 묻는다 |
| 푸시 전 점검 실패 · 충돌 · 병합 거부 · 권한 문제 | 알린다. **고치려 들지 않는다**(충돌 해결 · 테스트 수정을 하지 않는다) |
| `unknowns`에 병합 · 워크트리를 확인하지 못했다는 말이 있다 | 알리고 묻는다 |

## 하지 않는 일
- 다른 세션의 것 · 원래 저장소에서 띄운 도커 · 공용 이미지 · 볼륨을 건드리지 않는다.
- 로드맵 · 작업 카드를 여기서 마무리하지 않는다(`inProgress`는 보고만).
- 예약 작업 · `/loop`는 다루지 않는다.
