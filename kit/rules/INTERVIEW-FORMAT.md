# 면접 질문 만들기 (Claude · GPT 공통)

Claude의 `/interview` 커맨드와 Codex의 `interview` 스킬이 모두 이 파일을 따른다.
작업 카드에 쌓인 **실제 경험**으로 예상 면접 질문과 답변 뼈대를 만든다.

## 입력
- 대상: 사용자가 마일스톤(예: `M3`)이나 항목 ID를 주면 그것만, 아무것도 주지 않으면 **가장 최근에 끝난 마일스톤**.
- 읽을 것: `~/.work-dash/roadmaps/<프로젝트 이름>.md`에서 **대상 마일스톤 절만**, `~/.work-dash/worklogs/<프로젝트 이름>/*.md` 중 대상 항목의 카드.
  - 카드는 질문의 재료가 되는 절을 읽는다: `무엇을 했나` · `왜 이렇게 했나` · `바뀐 것` · `막혔던 문제와 해결` · `검증` · `리뷰 결과` · `학습 노트`. 건너뛰는 것은 `계획`과 `API · 스키마 상세`뿐이고, 설계 질문을 쓸 때는 `API · 스키마 상세`도 읽는다.
  - 정의서 카드는 `확정 사항`과 `왜 이렇게 했나`만 읽는다.
  - 커밋 메시지(`git log`)는 카드에 근거가 부족한 질문에만 본다. 코드는 읽지 않는다.
- 카드가 없는 항목은 질문을 만들지 않고, 마지막에 "카드가 없어 제외한 항목"으로 알린다.

## 출력
- 위치: `~/.work-dash/interview/<프로젝트 이름>.md`. 개인용이며 저장소에 커밋하지 않는다.
- 파일이 있으면 덮어쓰지 말고 `## <마일스톤 이름> (<날짜>)` 절을 아래에 추가한다. 같은 마일스톤 절이 이미 있으면 사용자에게 다시 만들지 묻는다.
- 질문은 마일스톤당 5~8개. 아래 종류를 골고루 섞는다: 기술 선택 이유 · 문제 해결 · 트레이드오프 · 설계 · 협업이나 회고.

```markdown
## M3. 공동구매 주문 (2026-10-20)

### Q1. 동시에 결제와 취소가 들어오는 문제를 어떻게 해결했나요?
- 면접관이 확인하려는 것: 동시성 문제를 인지하고 적절한 해결책을 고를 수 있는지
- 답변 뼈대 (상황 → 과제 → 행동 → 결과):
  - 상황: 공동구매에서 마지막 참여자의 결제와 결제 기한 만료 취소가 같은 주문을 동시에 바꿀 수 있었다
  - 과제: 결제는 됐는데 주문이 취소되는 일을 막아야 했다
  - 행동: 주문 조회에 비관적 락(SELECT … FOR UPDATE)을 걸고, 동시성 테스트로 두 요청을 동시에 보내 확인했다
  - 결과: 테스트에서 한쪽만 반영되는 것을 확인했다
- 꼬리 질문:
  - 낙관적 락은 왜 안 썼나요? → 충돌이 곧 돈 문제라 실패 후 재시도보다 처음부터 막는 게 맞았다
  - 데드락은 걱정 안 했나요? → 항상 주문 → 결제 순서로 잠그게 했다
- 근거: worklogs/SORD-8.md
```

## 규칙
- **카드와 커밋에 있는 사실만** 쓴다. 성과를 부풀리지 않는다 (예: 테스트로 확인한 것을 "운영에서 검증"이라고 쓰지 않는다).
- 답변 뼈대는 사용자가 **자기 말로 말할 수 있게** 짧은 문장으로 쓴다. 외워서 읽는 문장이 되지 않게 한다.
- 카드 근거가 약한 부분은 `(카드에 근거 없음 — 직접 확인 필요)`라고 표시한다.
- AI가 대부분 구현한 항목이라도 사용자가 내린 결정과 확인한 내용 위주로 쓴다. 사용자가 설명하지 못할 내용은 꼬리 질문에서 "이 부분은 다시 공부할 것"으로 표시한다.
- 마지막에 이번에 만든 질문 수와, 답하기 어려울 것 같은 질문(공부가 필요한 부분)을 짧게 알려 준다.
