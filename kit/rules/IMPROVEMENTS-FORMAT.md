# 개선 기록 형식 (Claude · GPT 공통)

**전과 후를 비교할 수 있는 변화**를 프로젝트별로 모아 두는 파일이다. 나중에 "무엇을 얼마나 바꿨나"를 숫자와 함께 설명하는 자료로 쓴다. 개선 기록을 쓰기 직전에 이 문서를 읽는다(세션에서 한 번).

- 위치: `~/.work-dash/improvements/<프로젝트 이름>.md`. 개인용이며 저장소에 커밋하지 않는다.
- `work-dash` 앱의 "개선 기록" 탭(학습 노트 옆)이 이 파일을 읽는다. 같은 탭 아래쪽에는 작업 카드의 `## 막혔던 문제와 해결` 절이 자동으로 모인다. 그것을 여기에 옮겨 적지 않는다.

## 무엇을 적나
- **적는다:** 느리던 것을 빠르게, 비싸던 것을 싸게, 자주 깨지던 것을 안 깨지게, 손으로 하던 것을 자동으로 바꾼 일. 원인을 찾는 데 오래 걸린 문제 해결.
- **적지 않는다:** 기능을 새로 만든 것(로드맵), 발견만 하고 고치지 않은 문제(이슈), 배운 개념(작업 카드의 학습 노트), 흔한 버그 수정.
- 기준은 "전 → 후를 한 줄로 쓸 수 있는가"다. 쓸 수 없으면 개선 기록이 아니다.

## 언제 적나
- 로드맵 항목을 끝낼 때 그 작업이 위 기준에 들면 기록 하나를 더한다. 사용자가 "기록해 둬"라고 할 때도 적는다.
- 숫자를 나중에 재게 되면 새 기록을 만들지 않고 그 기록의 `전 → 후`와 `재는 방법`을 고친다.

## 형식
```markdown
# <프로젝트> 개선 기록

## 2026-11-11 압축 버튼이 입력창의 글을 그대로 전송하던 문제
- 종류: 문제 해결
- 관련: WEB-40
- 문제: 무엇이 나빴나. 누가 어떤 상황에서 겪었나
- 원인: 왜 그랬나 (추정이면 추정이라고 쓴다)
- 해결: 무엇을 바꿨나
- 전 → 후: 3번 시도 중 3번 잘못 전송 → 0번 (측정)
- 조건: (세션 기록에서 나온 값일 때) 전 10-28~11-03 · 후 11-04~11-10, 프로젝트, 모델, 도구 버전
- 품질 확인: (비용을 줄였을 때) 나빠진 것이 없는지 무엇으로 봤나
- 재는 방법: 서버 기록의 시도 3건과 고친 뒤 직접 눌러 본 결과
- 남은 것: 아직 확인하지 못한 것, 부작용
```

- **기록 하나 = `## <날짜> <제목>`.** 날짜는 바꾼 날(`YYYY-MM-DD`). 제목은 무엇이 어떻게 됐는지 명사구로 쓴다. 새 기록을 파일 맨 위(제목 줄 바로 아래)에 둔다.
- **종류:** `비용` · `성능` · `안정성` · `문제 해결` · `작업 방식` 중 하나.
- **관련:** 로드맵 항목 · 이슈 ID(`RULES.md`의 "무엇을 어디에 쓰나"에 적힌 모양). 없으면 줄을 뺀다.
- **전 → 후:** 숫자와 단위를 쓰고, 줄 끝에 `(측정)` · `(관찰)` · `(어림)` 중 하나를 반드시 붙인다. 숫자가 없으면 상태로 쓴다(`두 번 눌러야 실행 → 한 번`).

| 표시 | 뜻 | 예 |
|---|---|---|
| `(측정)` | 하던 작업과 무관하게 정해지는 값을 직접 쟀다. 이 변경이 그 차이를 만들었다고 말할 수 있다 | 새 세션 첫 응답의 입력 크기, 실패 횟수 |
| `(관찰)` | 평소 기록에서 바꾸기 전 구간과 뒤 구간을 비교했다. 구간마다 하던 작업이 달라 이 변경 덕분이라고 단정할 수 없다 | 요청당 입력 토큰의 중앙값, 세션당 압축 횟수 |
| `(어림)` | 재지 않고 계산했거나 감으로 잡았다 | 파일 크기로 계산한 토큰 수 |

- 여러 건을 모은 값은 **중앙값과 건수**를 쓴다(`중앙값 9.1만(41건) → 7.4만(38건)`). 평균만 쓰지 않는다.
- **조건:** `(측정)` · `(관찰)` 값이 세션 기록에서 나왔으면 반드시 쓴다. 전 구간과 후 구간의 날짜, 대상 프로젝트, 모델, 도구 버전처럼 값을 바꿀 수 있는 것을 적는다. 전후로 달라진 조건이 있으면 그것도 적는다.
- **품질 확인:** 비용을 줄인 기록에 쓴다. 줄인 대신 나빠진 것이 없는지 무엇으로 봤는지 적는다(같은 기간의 다시 읽기 횟수, 실패 횟수 등). 보지 못했으면 "확인하지 못함"이라고 쓴다.
- **재는 방법:** 다른 사람이 같은 숫자를 다시 얻을 수 있게 쓴다(명령, 기록 위치, 기간, 건수).
- 한 줄에 한 가지. 길어지는 설명은 관련 작업 카드에 두고 ID로 가리킨다.
- 지어내지 않는다. 재지 않은 숫자를 `(측정)`으로, 구간 비교를 `(측정)`으로 쓰지 않고, 모르는 원인은 "확인하지 못함"이라고 쓴다.

## 동시 수정 규칙
고치기 직전에 고칠 줄만 다시 읽고, 바뀌는 줄만 고친다.
