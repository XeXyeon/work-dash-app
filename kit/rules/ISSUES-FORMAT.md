# 이슈 형식과 동작 (Claude · GPT 공통)

Claude의 `/issue` 커맨드와 Codex의 `issue` 스킬이 모두 이 파일을 따른다.
로드맵은 **계획한 일**, 이슈는 **작업하다 발견한 문제**(버그, 질문, 개선, 기술 부채)다. 이슈를 로드맵에 섞지 않는다.

## 이슈 파일
- 위치: `~/.work-dash/issues/<프로젝트 이름>.md`. 개인용이며 저장소에 커밋하지 않는다.
- `work-dash` 앱의 로드맵 화면(항목 아래)과 이슈 탭이 이 파일을 읽는다.

```markdown
# <프로젝트> 이슈

- [~] ORD-1#1 [중간][버그] 결제 대기 주문이 중복 생성됨 (발견: FE:ORD-1) @claude
  - 재현: 주문하기 버튼을 빠르게 두 번 클릭
  - 원인: 같은 장바구니 상품의 결제 대기 주문을 확인하지 않음
  - 해결 방향: 결제 대기 주문이 있으면 409 + 기존 주문 ID
- [x] ORD-1#2 [낮음][버그] 배송지 미선택 시 500 ✓2026-10-20 15:10
  - 해결: 요청 검증 추가, 400으로 응답
  - 커밋: a1b2c3d
- [ ] ISS-1 [중간][설정] dev 설정 키 3개 누락 (관련: ORD-2, SHOP-1)
- [-] ISS-2 [낮음][질문] operationId 중복 — 의도된 동작이라 닫음 ✓2026-10-20 16:00
  - 이유: 팀 규칙상 operationId를 따로 지정하지 않음
```

- 줄의 모양(번호 · 상태 기호 · 담당 태그 · 괄호 정보 · `해결:` · `이유:`)은 아래 "명령으로 바꾼다"의 명령이 쓴다. 손으로 쓴 줄이 틀리면 문서 검사가 고칠 방법을 알려 준다.
- **상태:** `[ ]` 열림 · `[~]` 처리 중 · `[x]` 해결 · `[-]` 해결하지 않고 닫음(의도된 동작, 중복, 보류)
- **ID:** 로드맵 항목에서 생긴 이슈는 `<항목 ID>#<번호>`, 어느 항목에도 속하지 않는 공통 이슈(환경 · 설정, 여러 기능에 걸친 문제, 아직 항목이 없는 영역, 정책 질문)는 `ISS-<번호>`. 한 번 붙인 ID는 바꾸지 않는다.
- **심각도:** `[높음]` 기능이 안 되거나 데이터 · 보안 문제 · `[중간]` 일부가 잘못 동작 · `[낮음]` 불편이나 표시 문제
- **세부 줄:** 이슈 줄 아래 두 칸 들여써서 `- 재현:` `- 원인:` `- 해결 방향:` `- 해결:` `- 이유:` `- 커밋:`을 필요한 것만 쓴다.
- 줄 끝의 시각 `✓…`은 work-dash가 붙이니 붙이거나 지우지 않는다.

## 어디에 적나
- **고칠 곳**의 프로젝트 이슈 파일에 적는다. 프론트엔드 작업 중 백엔드 문제를 발견했으면 **백엔드 이슈 파일**에 `(발견: <FE 프로젝트의 접두어>:<항목 ID>)`로 적는다. 접두어는 로드맵의 교차 참조와 같다(`~/.work-dash/config.json`의 `projects.<프로젝트 이름>.key`, 없으면 프로젝트 이름). 두 프로젝트가 같은 `~/.work-dash/issues/` 폴더를 쓴다. 프론트와 백엔드가 한 프로젝트로 묶여 있으면 이슈 파일도 하나이므로 `발견:` 표기가 필요 없다.
- 부모 항목은 **고칠 곳의 로드맵 항목**이다. 맞는 항목이 없으면 공통 이슈(`ISS-n`)로 적는다.
- 이미 완료된 항목에서 다시 생긴 문제도 그 항목 아래(`<ID>#n`)에 적는다. 항목은 완료 상태로 둔다.
- **팀원 코드나 팀원이 알아야 하는 문제**는 팀 GitHub Issues에 올리고, 여기에는 `(GitHub: #번호)`만 남긴다.
- 이슈를 고치는 일이 기능 하나만큼 커지면 로드맵 항목으로 **승격**하고, 이슈는 `[-]`로 닫으며 `- 이유: <새 항목 ID>로 이동`을 남긴다.

## 명령으로 바꾼다
이슈의 번호 · 상태 · 담당 태그 · `해결:` · `이유:` 줄은 손으로 쓰지 않고 명령이 쓴다. 프로젝트는 현재 폴더로 찾는다. Codex는 `--as gpt`를 붙인다.

```bash
node ~/.work-dash/app/core/item.js issue                # 열린 · 처리 중 이슈(심각도 순)
node ~/.work-dash/app/core/item.js issue add --parent <항목 ID|ISS> --sev <높음|중간|낮음> --kind <버그|질문|개선|설정|기술부채> "<제목>" [--detail "재현: …"]
node ~/.work-dash/app/core/item.js issue start <ID>
node ~/.work-dash/app/core/item.js issue resolve <ID> "<무엇을 바꿨는지>" [--commit <해시>]
node ~/.work-dash/app/core/item.js issue close <ID> "<이유>"
```

- `add`: 부모 후보가 둘 이상이면 원인이 있는 코드를 가장 최근에 바꾼 항목을 부모로 하고 나머지는 `--related`로 준다. 다른 프로젝트에서 고칠 문제면 `--project <이름>`, 다른 곳에서 발견했으면 `--found <접두어:ID>`. 명령이 같은 부모의 열린 이슈를 함께 보여 주니, 같은 문제가 이미 있으면 방금 넣은 줄을 지운다.
- 세부 줄을 손으로 더할 때는 그 이슈의 줄만 다시 읽고 그 줄만 고친다. 다른 에이전트가 `[~]`로 잡은 이슈는 사용자가 시킬 때만 바꾼다.
