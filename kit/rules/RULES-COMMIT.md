# 커밋 · PR 규칙 (Claude · GPT)

**커밋 · 푸시 · PR을 만들기 직전에** 읽는다(세션에서 한 번).

프로젝트에 커밋 규칙이나 PR 템플릿이 있으면 그것을 먼저 따르고, 아래는 그 위에 더한다.

- **커밋 하나 = 논리적 변경 하나.** 그 커밋만 체크아웃해도 컴파일되고 관련 테스트가 통과해야 한다. 구현과 그 테스트는 같은 커밋에 둔다. 언제 나누는지는 항목을 시작할 때 명령이 알려 준다.
- **메시지:** 제목은 무엇을 했는지 한 줄. 본문에는 왜 그렇게 했는지를 쓴다.
- **PR 본문:** 아래 절을 이 순서로 쓴다. 해당 없는 절은 빼고, 프로젝트 템플릿의 칸(이슈 번호 등)은 그대로 채운다.
  1. 요약 — 이 PR로 무엇이 가능해지는지 2~3문장
  2. 주요 결정 — 결정, 이유, 버린 대안 (설계 문서가 있으면 그 절을 링크)
  3. 변경 내용 — 커밋별 또는 영역별 한 줄
  4. API · 스키마 변경 — 엔드포인트, 요청 · 응답, 테이블 · 컬럼
  5. 검증 — 실행한 명령과 결과, 직접 확인한 것과 확인하지 못한 것
  6. 리뷰 포인트 — 특히 봐야 할 곳, 알려진 한계, 후속 작업
- PR에 에이전트 · 세션 이름을 쓰지 않는다.
