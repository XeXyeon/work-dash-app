# 개발 로드맵

이 앱을 만드는 동안 실제로 쓴 로드맵을 읽기 좋게 간추린 것입니다. 원본은 앱이 읽는 것과 같은 형식의 마크다운 파일이고, 에이전트(Claude Code · Codex)와 사람이 함께 고쳤습니다.

## 한눈에

| | |
|---|---|
| 기간 | 2026-11-09 ~ 2026-11-27 (19일) |
| 커밋 | 약 160개 |
| 병합한 PR | 44개 |
| 마일스톤 | 16개 (모두 끝난 것 10개) |
| 항목 | 115개 중 104개 완료 · 1개 취소 |

- 숫자는 공개 전 개발 저장소 기준입니다. 이 저장소는 공개용으로 새로 올려서 커밋이 하나로 시작합니다.
- 마일스톤 번호는 만든 순서이고, 아래 순서는 대략 끝난 순서입니다.
- 로드맵 형식과 파서, 터미널 화면은 이 앱 전부터 있었습니다. 여기 적힌 것은 그 위에 화면과 앱을 만든 기간입니다.
- 마일스톤 하나는 "끝나면 직접 확인할 수 있는 결과 하나"로 잡았습니다. 그래서 각 마일스톤에 **완료 기준**이 한 줄씩 있습니다.

## 마일스톤별로 만든 것

### M1. 대시보드 화면
가장 먼저 정의서(화면 구성 · 데이터 읽기 방식 · 기술 선택)를 쓰고 시작했습니다.

- 로컬 서버: 로드맵 · 이슈 · 작업 카드를 읽는 API와 파일 변경 감지(SSE)
- 로드맵 화면: 프로젝트 목록, 진행률, 마일스톤 접기, 이슈 배지
- 이슈 화면과 작업 카드 · 이슈 카드 패널
- 흐름 문서 화면(Mermaid), 규칙 · 형식 문서 화면
- 프로젝트 보관 · 삭제, 플러그인 · 스킬 화면

### M2. 데스크톱 앱 (Tauri)
브라우저 탭에서 독립 창으로 옮겼습니다. 앱 틀과 백엔드를 어떻게 할지는 [주요 결정](decisions.md#3-데스크톱-앱은-tauri-백엔드는-node-그대로)에 있습니다.

- Tauri 앱 창: 떠 있는 서버를 쓰거나 없으면 띄움, 서버가 안 뜰 때의 화면
- 메뉴 막대 상주: 진행 중 요약, 창을 닫아도 남음, 종료할 때 서버 정리
- `/Applications` 설치 명령과 앱 아이콘
- 브라우저 · 터미널 전용 코드 정리

### M6 · M8. 로드맵 형식 넓히기
쓰다 보니 필요해진 것들입니다.

- 외부 대기 · 보류 · 취소 상태와 선행 계산, 진행률 분모 규칙
- 폴더 여러 개를 프로젝트 하나로 묶기, 다른 로드맵의 항목을 선행으로 가리키기
- 프로젝트 표시 이름 바꾸기

### M9. 기획 · 학습 노트 화면
- 저장소 `docs/` 문서를 읽는 기획 탭
- 작업 카드의 학습 노트를 개념별로 모으는 탭
- 본문의 항목 · 이슈 ID 자동 링크, `§` 절 참조 상자
- 개선 기록 탭(전 → 후 숫자, 측정인지 어림인지 표시)

### M4. 세션 알림
여러 에이전트 세션을 동시에 돌릴 때 "누가 나를 기다리나"를 보려고 만들었습니다.

- 세션 알림 카드 목록: 입력 대기 · 작업 중 · 끝남
- 대화 열기: Claude 데스크톱 앱 · ChatGPT 앱 · iTerm으로 그 세션을 엶
- 오늘 비용 · 토큰, 세션별 컨텍스트 크기와 압축 버튼
- 세션 종결 점검 스크립트
- 남은 4개는 세션 종결을 버튼 하나로 묶는 일이었고, 앱을 멈추면서 진행하지 않았습니다.

### M10 · M12. 검사로 지키는 규칙
항목 수로는 가장 큰 마일스톤입니다. 에이전트에게 준 규칙이 글로만 있으면 잘 지켜지지 않아서, 규칙을 린터 · 훅 · 명령으로 옮겼습니다. 배경은 [주요 결정](decisions.md#5-규칙을-글에서-검사로-옮긴다)에 있습니다.

- 문서 린터: 로드맵 · 작업 카드 · 이슈 형식, 없는 ID 참조
- 문서를 고친 직후의 검사 훅, 커밋 · PR 명령 앞의 검사 훅
- 큰 문서를 통째로 읽는 호출을 막고 항목 하나만 보여 주는 명령
- 바뀐 파일을 보고 돌릴 확인만 고르는 명령, 푸시 앞 전체 확인
- 항목 · 작업 카드를 만드는 명령(형식을 외우지 않아도 되게)
- 훅이 막은 것 · 건너뛴 것의 기록
- 검사 자체의 시험, 임시 홈 폴더 설치 시험과 서버 확인
- 검사가 대신하게 된 줄을 규칙 문서에서 지우는 일(여러 차례)

### M3. 화면 맞춤 설정
- 패널 · 사이드바 폭 드래그와 기억
- 프로젝트 순서 바꾸기(끌어 놓기 · 키보드)
- 마일스톤 접기 상태 저장
- 다크 모드 · 글꼴 설정과 이슈 상태 변경은 하지 않았습니다.

### M13. Codex 구현 넘기기
- 넘기기 정의서: 비대화식 실행 옵션, 권한 방식, 완료로 받는 조건, 멈추는 조건
- 손으로 한 번 넘겨 본 시험
- 항목 ID로 워크트리를 만들고 Codex를 돌린 뒤 확인까지 하는 명령

### M11. 설치와 공개 준비
혼자 쓰던 도구를 다른 기기 · 다른 사람이 받을 수 있게 만드는 일이었습니다.

- 설치 구조 정의서: 무엇이 저장소의 것이고 무엇이 개인 설정인지
- `init`(미리 보기 · 백업 · 훅 등록)과 `uninstall`(넣은 것만 되돌림)
- 환경 점검과 설정 페이지(꼬인 곳을 보여 주고 버튼으로 고침)
- 기록 도구(규칙 · 파서 · 훅)를 앱에서 떼어 내기
- 공개 전 점검: 예시 데이터로 스크린샷 교체, 코드 안의 개인 정보 제거, 라이선스

### M14 ~ M16. 다른 에이전트 앱으로 옮기기
평소 쓰는 에이전트 앱의 사이드바에 같은 보기를 플러그인으로 넣었습니다. 만들고 보니 이 앱은 기록을 보는 여러 화면 가운데 하나가 됐고, 그래서 기록 도구를 앱에서 떼어 냈습니다(M11). 그 뒤 화면은 플러그인 쪽을 쓰기로 하면서 이 앱은 여기서 멈췄습니다.

- Orca · Paseo 사이드바의 로드맵 패널
- Paseo 플러그인에 이슈 · 흐름 · 기획 · 학습 노트 · 개선 기록 보기 추가

### M5. Rust 백엔드 전환 판단
Node 서버를 Rust로 다시 쓸지 정하려고 앱 전체 메모리를 쟀습니다. 측정과 원인 확인까지 했고, 결정하기 전에 앱을 멈췄습니다. 측정 결과는 [주요 결정](decisions.md#4-rust로-다시-쓰기-전에-먼저-잰다)에 있습니다.
